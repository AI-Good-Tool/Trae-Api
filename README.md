**0.3.2**：参考本机 Trae 图标重新设计白色圆角底、几何双眼与黑绿双向切换框，更新侧栏、Dock 和 macOS 安装包。账号池卡片增加积分包数量、近期到期明细与全部积分包弹窗，直接提供手动签到和自动签到开关。保留 双区联合模型路由、按模型独立轮询 / 顺序优先 / 随机调度、模型别名与地区设置、请求记录同时显示别名和真实模型，以及签到历史和启动补签。审查说明见 [docs/REVIEW-0.3.0.md](docs/REVIEW-0.3.0.md)。

参考本机 Qoder Switch 的账号、用量、签到与网关模块，重新设计的 Trae / Trae CN 本地工作台。独立工程，不修改参考项目。浅色鼠尾草绿界面，支持浏览器工作台和 Electron 桌面窗口。

## 启动

```sh
npm start
# 浏览器访问 http://127.0.0.1:19827

npm run desktop
# 独立桌面窗口，复用同一个本地后台

npm test
npm run inspect -- --live

npm run build:mac
# 在 macOS 本机架构下生成 .app、DMG 和 SHA-256 校验文件
```

也可执行 `zsh "启动 Trae Switch.command"`。首次使用桌面窗口需 `npm install` 下载 Electron；浏览器工作台只依赖 Node.js 22+。

macOS 安装包位于 `dist/mac-0.3.2/`，拖动应用至 Applications 即可使用，无需安装 Node.js。当前构建为 Apple Silicon（arm64），采用本地 ad-hoc 签名，未做 Apple Developer ID 公证。

## 地区、密钥与记录

- 国内 Base URL：`http://127.0.0.1:19828/cn/v1`；国际：`http://127.0.0.1:19828/intl/v1`。`/v1` 跟随工作台已保存的地区。
- 选择“双区联合”后，统一 /v1 使用两个地区的有效账号：同一真实模型跨地区轮询，独有模型只使用实际提供它的账号。每个模型单独维护轮询顺序。也可选择顺序优先、随机或指定账号；一次请求只发送给一个账号，不自动重放上游请求。固定地区地址仍只使用对应地区账号。
- 模型目录可编辑对外别名和允许地区，加密持久化；/models 和响应使用别名，仍兼容真实模型名称及无歧义配置 ID。向上游发送当前账号的真实配置 ID；请求记录快照保留别名、真实模型、配置 ID 与实际账号地区。目录变化导致名称歧义时拒绝路由。
- 签到仅适用于官方提供入口的国内账号，支持单个 / 全部签到、按账号自动签到、启动补签、北京时间跨日判断及最近 300 条执行历史。自动签到需要保持应用运行，每 10 分钟检查一次；并发操作合并，领取前查状态、领取后确认。
- 两地区共享本地 API Key，可编辑为 16–128 位安全 ASCII 字符，或使用 crypto 随机生成；更新后旧密钥立即失效。
- 请求记录按最近 1,000 条保留运行元数据，包含时间、地区、模型、账号、Token、协议、HTTP 状态、耗时、结果和错误代码。不保存输入 / 输出正文及认证令牌，随账号库加密保存在本机。
- 图标为可编辑的矢量设计 `ui/icon.svg`，使用白色圆角底、菱形双眼与黑绿双向箭头表达账号切换；`npm run icons` 可复现 PNG、iconset 与 ICNS。

## 实测限制

2026-10-21，本机 Trae CN 3.4.4、Trae 3.6.4：

- 国内版用量接口首次返回 4,600 积分、已消耗 0；签到查询返回今日已领取 100 积分。
- 国际版返回美元账期额度与实际消耗，不能与国内版积分相加。
- 原生 `get_detail_param` 当前仅返回 FastApply 等配置。`llm_utils_chat` 已收到 SSE `output.response`，但默认配置返回 FastApply 类内容，部分模型调用返回 4023（未知模型），不能宣称通用模型反代已打通。
- `ModularData/ai-agent/database.db` 使用 SQLCipher，加密会话库的历史 Token 尚未接入。界面不生成虚假历史曲线或估算 Token。
- 国际版未提供相同的国内签到入口。自动签到需要后台运行，不安装系统定时任务。
- 当前只支持 macOS 客户端存储位置。Responses、Anthropic Messages、工具调用尚未适配。

## 数据与实现

数据位于 `~/.trae-switch/`，账号库使用 AES-256-GCM，密钥与加密文件仅允许本用户读写。密钥文件与密文同处本机目录，因此不能抵御已取得本机用户权限的程序。客户端写入前备份位于 `backups/`，不在源码目录保存真实凭证。

工作台绑定 127.0.0.1，使用 HttpOnly / SameSite Cookie、Host 和 Origin 检查。网关独立绑定 127.0.0.1:19828，使用 Bearer Key 认证。上游地址从本机客户端 product.json 读取，诊断命令可显示实际目标域名；不任意转发客户端提供的 URL。

后端使用 Node 内置模块，按客户端存储、加密库、官方接口、OAuth、网关分离职责。前端为原生 HTML/CSS/JS，保持依赖简单。没有复制 Qoder 的协议或凭证，也没有执行 Git 提交或创建分支。

研究依据及后续适配细节见 [docs/RESEARCH.md](docs/RESEARCH.md)。
